队员用 DeepSeek 编写独立的 TypeScript 核验模块；当前对话负责模型接入、协调员、任务调度、后端和界面集成。队员拥有明确的代码模块，可以独立测试后交回合并。

## 开始方式

优先从共享 GitHub 仓库克隆代码，并按 [GitHub 协作指南](GitHub协作指南.md) 创建自己的分支。也可把 `队员开发起步包.zip` 发给队员，解压进入 `app`。包内为当前通用模型版源码，不含真实模型密钥、依赖目录或构建缓存。双方使用 `src/lib/agents/plan-contract.ts` 中的共同类型，不各自重新定义接口；需要调整时先列出建议。

只新增三个文件：

1. `src/lib/agents/plan-verifier.ts`：导出纯函数 `verifyPlan(request: PlanRequest, plan: PlanCandidate): PlanVerification`。
2. `tests/plan-verifier.test.mjs`：使用 Node 自带测试框架测试。
3. `docs/核验模块说明.md`：说明规则、假设、命令、实际测试结果与局限。

可读取其他源码，本轮不修改共同类型、模型客户端、聊天 API、页面、依赖和锁文件。函数不调用模型、不请求网络、不读取密钥、不生成随机数据、不依赖当前日期时间，也不修改传入对象。

## 接口含义

输入分成两部分，不能让生成计划自行修改用户约束：`request` 是调用方保留的校区、可用时间、原始任务、任务开放窗口和资料证据；`plan` 只有模型生成的执行步骤，步骤通过 `taskId` 对应原始任务。时间均为同一天的 `HH:mm`，按分钟比较；不处理跨午夜。校区和可用时间允许缺失，此时返回需要补充信息。共同接口样例见 `docs/计划核验接口样例.json`。

输出每条问题的代码、严重程度、相关步骤、原因和修正建议。状态优先级：有 `error` 则 `revise`；否则有 `needs_info` 则 `needs_info`；否则 `passed`。warning 可随 passed 返回，但 passed 不表示全部现实事实已核实。

## 必须实现的规则

| 检查 | code | severity 与要求 |
| --- | --- | --- |
| 缺 request 校区、可用时间、任务、plan 步骤或步骤起止时间 | missing_input | needs_info，指出需要补充什么 |
| 原始任务未覆盖、同一任务重复安排、计划引用未知 taskId、原始任务 id 重复 | task_coverage | error；第一版约定每个原始任务恰好对应一个步骤 |
| 非法 HH:mm，或结束不晚于开始 | invalid_time | error；无效区间不再参与时间比较 |
| 步骤超出 request 可用时段 | outside_available_window | error；不能只核对步骤之间而忽略用户约束 |
| 任意两步骤时间重叠 | time_overlap | error；end 等于下一步 start 不重叠 |
| 步骤校区与选定校区不一致 | campus_mismatch | error；本版本不做跨校区计划 |
| 步骤 id 重复、依赖 id 不存在、依赖循环、依赖未在本步骤前结束 | dependency_conflict | error；不能因循环而死循环 |
| 步骤超出 request.tasks 中对应任务的开放时段 | outside_service_window | error；开放时段本身格式错误用 invalid_time |
| 步骤没有依据、引用不存在的 evidence id 或证据 id 重复 | missing_evidence | needs_info |
| 使用未核实的真实依据，或真实计划使用模拟依据 | unverified_evidence | needs_info；request.simulation=true 时允许 simulation 依据，official/project 必须 verified=true |
| request.tasks 中的对应任务没有开放时段 | unknown_service_window | warning；不编造开放时间 |

核验器只检查输入内部一致性及证据标记，不访问网页，不判断引用是否真实，不推算真实步行时间。路线与真实资料核对由后续其他环节负责。

## 测试与验收

至少测试：合法计划、相邻不重叠、包含型时间重叠、超出用户时间、跨校区、缺校区/时间、非法时间、任务遗漏/重复、未知 taskId、依赖不存在、依赖循环、依赖顺序错误、依据缺失、真实计划用模拟依据、未核实依据、模拟计划允许模拟依据、开放时段冲突、两份输入均未被修改。

使用 Node.js 22.18+ 或 24，在 app 根目录执行：

```text
node --experimental-strip-types --test tests/plan-verifier.test.mjs
```

实现文件引用类型采用 `import type { ... } from './plan-contract'`，测试文件采用 `import { verifyPlan } from '../src/lib/agents/plan-verifier.ts'`。不新增依赖，不使用需转译的枚举或构造函数参数属性。
