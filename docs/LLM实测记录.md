## 模型做了什么、没做什么

模型负责四件事：规划（拆子任务）、生成分析脚本、诊断失败类型、撰写结论叙述。
**判定权不在模型手里**——是否通过由 L1–L4 的机器判据给出。

三个可核对的例子：

1. **T-07**：模型生成的脚本（1509 字符）通过静态检查被采用 → 第 1 轮因注入的依赖缺失被 L2 拦下（`ModuleNotFoundError: No module named 'nonexistent_dep_xyz'`）→ 修正动作按边界回退到已验证模板 → 第 2 轮 exit=0、`diff=2.630822`、`n=60/60` 通过。
2. **T-10**：两次尝试都被判 `tool_fail`，第 2 轮触发 `stop reason=strategy_dedup`（同一失败类型重复同一策略 → 继续重试无意义），判死放弃而不是烧 token 硬试。
3. **诊断一致率**：本轮共 3 次失败诊断（T-06 `input_data`、T-07 `tool_fail`、T-10 `tool_fail`），模型分类与规则分类 **3/3 一致**（`agree=true`），且模型给出的修正建议（重新取数、换工具）正是系统实际执行的策略。
